# HackMate 产品需求文档（PRD）

> 阶段：MVP / 开发阶段  
> 产品形态：本地运行的桌面端 Web 应用  
> 依据：`docs/idea.md`、`docs/draft-edited.md`、`AGENTS.md`

## 1. 产品概述

HackMate 是一个黑客松现场组队网页应用。用户可以在广场浏览队伍、创建队伍、申请加入队伍；队长可以审核申请、管理成员并完成组队。

本阶段目标是让用户完成“浏览 / 创建队伍 → 申请 → 审核 → 加入队伍 → 查看我的队伍”的完整闭环。

## 2. 用户角色

| 角色 | 说明 |
| --- | --- |
| 游客 | 未登录用户，可浏览广场和队伍详情，不能进行队伍操作或查看联系方式。 |
| 登录用户 | 已完成注册并登录的用户。 |
| 申请人 | 已提交申请、等待队长审核的用户。 |
| 队伍成员 | 申请已通过并加入队伍的用户。 |
| 队长 | 创建队伍并管理该队伍的用户。 |

## 3. 本阶段范围

### 3.1 实现范围

- 手机号 + 验证码注册、登录、退出登录。
- 广场、搜索和状态筛选。
- 队伍详情。
- 创建队伍。
- 申请加入队伍。
- 队长审核申请、移除成员、完成组队和重新开放招募。
- “我的队伍”和申请状态展示。
- 按权限展示手机号联系方式。
- 桌面端页面。

### 3.2 不实现范围

- PDF、图片、视频等附件上传。
- 头像上传及用户资料编辑，统一使用默认头像。
- 移动端适配。
- 活动名称、时间、地点、截止时间等活动上下文。
- 微信、群二维码、站内聊天等沟通方式。
- 队伍编辑、成员主动退出、转让队长、解散队伍。
- 申请人主动撤回待审核申请。
- 站内实时通知和消息推送。
- 验证码有效期、重发冷却、错误次数限制。
- 内容审核、举报和风控。

## 4. 核心用户流程

### 4.1 注册、登录与退出

1. 用户使用手机号获取 6 位验证码。
2. 开发阶段验证码直接显示在输入框下方。
3. 新手机号完成注册，填写昵称及选填资料。
4. 已注册手机号通过验证码登录。
5. 用户可随时退出登录，切换其他账号。

### 4.2 浏览与申请

1. 用户进入广场浏览队伍。
2. 通过关键词或队伍状态查找目标队伍。
3. 进入队伍详情查看项目、队长、人数、角色和招募要求。
4. 符合条件时提交申请，选择目标角色并填写文字介绍。
5. 申请人在“我的队伍”查看审批状态。

### 4.3 创建与组队

1. 登录用户创建队伍，填写项目信息、预设名额和招募角色。
2. 创建成功后用户成为队长，并自动成为队伍第一名成员。
3. 队长在队伍详情中审核申请，可同意或拒绝。
4. 通过申请的用户成为队伍成员，并可在队内查看成员联系方式。
5. 队长可手动将队伍标记为“已完成组队”，也可重新开放招募。

## 5. 功能需求

### 5.1 用户与登录

- 一个手机号只能对应一个账号。
- 注册时手机号、验证码、昵称必填。
- 学校/公司、技能标签、希望担任的角色、个人简介为选填。
- 用户资料在注册时确定，本阶段不支持编辑。
- 验证码为 6 位数字，由系统生成并在页面直接展示。
- 验证码必须正确，但不实现有效期、重发冷却和错误次数限制。
- 登录状态在刷新后保持。
- 页面顶部展示当前用户昵称和退出登录入口。

### 5.2 联系方式可见性

本阶段唯一联系方式为登录手机号。

| 场景 | 可见规则 |
| --- | --- |
| 游客 | 不可见任何手机号。 |
| 普通登录用户 | 不可见其他用户手机号。 |
| 申请人 | 待审核或已拒绝时，不可见队长和成员手机号。 |
| 队长 | 可查看申请人和已通过成员的手机号。 |
| 队伍成员 | 可在队伍详情中查看同队成员及队长的手机号。 |
| 广场队伍卡片 | 仅当查看者已经是该队成员时展示队长手机号。 |

### 5.3 广场

- 广场展示组队中和已完成组队的队伍。
- 默认筛选“组队中”，可切换“已完成组队”或“全部”。
- 支持按关键词搜索队伍名称、项目简介和招募角色。
- 队伍卡片展示：队伍名称、一句话介绍、队长昵称、队伍状态、当前人数 / 预设名额、各角色剩余名额、更新时间。
- 当前人数和预设名额均包含队长。
- 支持加载中、加载失败和空状态。
- 游客可以浏览广场和队伍详情。

### 5.4 创建队伍

- 只有未加入其他队伍的登录用户可以创建队伍。
- 创建队伍时，用户名下的待审核申请自动关闭。
- 必填字段：队伍名称、一句话介绍、完整项目介绍、预设名额、至少一个招募角色。
- 招募角色包含角色名称、计划招募人数和角色要求。
- 选填字段：项目方向/赛道、硬性要求、加分项。
- 预设名额至少为 1，包含队长，仅作为规划参考。
- 角色计划人数不包含队长，也仅作为规划参考。
- 创建成功后队伍状态为“组队中”，当前人数为 1。

### 5.5 队伍详情

- 展示项目信息、队长、队伍状态、当前人数 / 预设名额、成员列表、招募角色及剩余名额、硬性要求和加分项。
- 队长在成员列表中标记为“队长”。
- 实际人数可以超过预设名额，达到或超过时展示提示，但不自动停止审核。
- 角色实际人数达到或超过计划人数时，剩余名额显示为 0，但不阻止队长继续通过申请。
- 不展示活动名称、时间、地点或截止时间。

### 5.6 申请加入

- 只有未加入其他队伍的登录用户可以申请。
- 队伍状态必须为“组队中”。
- 同一个人不能对同一队伍重复提交待审核申请。
- 申请时必须选择目标角色，并填写最多 1000 字的文字介绍。
- 申请提交后状态为“待审核”，待审核期间不能修改。
- 本阶段不展示附件上传入口。
- 被拒绝后，在队伍仍处于组队中时可以重新申请。
- 用户最多加入或创建一个队伍，但可以同时拥有多个待审核申请。
- 任一申请通过、用户创建队伍后，其余待审核申请自动关闭并标记为已拒绝。

### 5.7 队长审核

- 队长可以查看申请人的昵称、手机号、资料、目标角色、文字介绍和申请时间。
- 队长可以同意或拒绝申请。
- 同意后申请人立即成为队伍成员，并获得申请时选择的目标角色。
- 通过申请不会自动停止招募或改变队伍状态。
- 拒绝理由选填，且对申请人可见。
- 已完成组队或申请人已加入其他队伍时，不能通过该申请。

### 5.8 队伍状态与生命周期

本阶段只有两个队伍状态：

- **组队中**：可以继续接收申请和审核成员。
- **已完成组队**：队长手动结束组队，不再接收新申请，也不能继续通过申请。

规则：

- 完成组队由队长手动触发，不要求达到预设名额。
- 完成组队时，所有待审核申请自动关闭，拒绝理由为“该队伍已完成组队”。
- 已完成组队后，队长可以重新开放招募，队伍恢复为“组队中”。
- 队长可以移除已通过成员，但不能移除自己。
- 被移除成员失去队内联系方式权限，可以申请或创建其他队伍。
- 本阶段不支持编辑队伍、成员主动退出、转让队长和解散队伍。

### 5.9 我的队伍

- 首页和顶部导航提供“我的队伍”入口。
- 展示用户作为队长或成员加入的队伍。
- 展示已提交但尚未加入的申请，并区分“待审核”和“已拒绝”。
- 已拒绝申请展示拒绝理由。
- 符合条件时，可从拒绝记录重新申请。
- 队长入口展示待审核申请数量。
- 本阶段不提供实时通知，状态变化在刷新或重新进入页面后展示。

## 6. 页面清单

| 页面 | 主要内容 |
| --- | --- |
| 登录/注册页 | 手机号、验证码、发送验证码、开发验证码提示、昵称及选填资料。 |
| 广场 | 搜索、状态筛选、队伍卡片、空状态和错误提示。 |
| 创建队伍 | 项目信息、预设名额、招募角色、要求和创建按钮。 |
| 队伍详情 | 项目信息、队长、人数、角色、成员、申请入口或队长管理入口。 |
| 申请加入 | 目标角色、文字介绍和提交结果提示。 |
| 我的队伍 | 已加入队伍、待审核申请、已拒绝申请、拒绝理由和重新申请入口。 |
| 队长审核 | 申请人资料、手机号、申请内容、申请时间、同意/拒绝操作及拒绝理由。 |

## 7. 权限矩阵

| 操作 | 游客 | 登录用户 | 申请人 | 队伍成员 | 队长 |
| --- | --- | --- | --- | --- | --- |
| 浏览广场和队伍详情 | 是 | 是 | 是 | 是 | 是 |
| 查看队伍成员手机号 | 否 | 否 | 否 | 是 | 是 |
| 查看申请人手机号 | 否 | 否 | 否 | 否 | 是 |
| 创建队伍 | 否 | 是 | 是 | 否 | 否 |
| 申请加入队伍 | 否 | 是 | 是 | 否 | 否 |
| 审核申请 | 否 | 否 | 否 | 否 | 是 |
| 移除成员 | 否 | 否 | 否 | 否 | 是 |
| 完成组队 / 重新开放招募 | 否 | 否 | 否 | 否 | 是 |

说明：登录用户创建或申请队伍时，不能已经加入其他队伍。

## 8. 验收标准

1. 新用户可以使用手机号和 6 位验证码注册，并填写昵称完成登录。
2. 已注册用户可以通过验证码登录，退出后可以切换另一个账号。
3. 游客可以浏览广场和队伍详情，但看不到手机号。
4. 登录用户可以搜索、筛选并查看队伍详情。
5. 登录用户可以创建队伍，并自动成为队长和第一名成员。
6. 用户可以提交包含目标角色和文字介绍的申请，并在“我的队伍”查看状态。
7. 队长可以看到申请人资料和手机号，并进行同意或拒绝。
8. 拒绝理由选填且对申请人可见，被拒绝后可以重新申请。
9. 申请通过后，用户可以成为队伍成员并查看同队成员手机号。
10. 队长可以手动完成组队，待审核申请自动关闭；重新开放后可以继续招募。
11. 队长可以移除成员，被移除成员失去队内联系方式权限。
12. 队伍实际人数可以超过预设名额，不会自动阻止队长审核。

## 9. 运行与技术约束

- 当前仅在本地运行，面向桌面端浏览器。
- 前后端分离。
- 后端使用 Python、FastAPI、SQLite，使用 uv 管理环境。
- 前端使用 React、Vite、TypeScript、Tailwind CSS、shadcn/ui、lucide-react。
- 本阶段不接入真实短信服务。
- 本阶段不实现文件、图片、视频上传。
