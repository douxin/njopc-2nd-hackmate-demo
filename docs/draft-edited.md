## 1. 产品定位

HackMate 是一个面向黑客松现场组队的网页应用，当前仅供本地开发与演示使用。

用户可以通过产品完成以下主流程：

1. 使用手机号和验证码注册、登录。
2. 在广场浏览队伍，查看队伍详情。
3. 创建队伍并成为队长。
4. 申请加入感兴趣的队伍，并等待队长审核。
5. 队长查看申请并同意或拒绝。
6. 申请通过后成为队伍成员，并查看队伍成员信息。
7. 通过“我的队伍”查看自己加入的队伍和申请记录。
8. 退出登录并切换其他账号。

## 2. 本阶段实现范围

### 2.1 本阶段实现

- 手机号验证码注册、登录、退出登录。
- 广场列表、关键词搜索、状态筛选。
- 队伍详情。
- 创建队伍。
- 申请加入队伍。
- 队长审核申请。
- 队长移除已通过的成员。
- 队长手动完成组队。
- 队长重新开放招募。
- “我的队伍”和申请状态展示。
- 手机号联系方式按权限展示。
- 桌面端页面。

### 2.2 本阶段不实现

- PDF、图片、视频等附件上传。
- 头像上传、头像编辑或头像裁剪；统一使用默认头像。
- 用户资料编辑。
- 申请人主动撤回待审核申请。
- 移动端适配。
- 活动名称、活动时间、活动地点、组队截止时间等活动上下文。
- 微信、微信群二维码、站内聊天等额外沟通方式。
- 队伍信息编辑。
- 成员主动退出队伍。
- 队长转让。
- 队伍解散。
- 站内实时通知、消息推送。
- 验证码有效期、重发冷却、错误次数限制等复杂验证码规则。
- 队伍、用户或申请的内容审核与举报功能。

## 3. 用户身份与资料

### 3.1 用户角色

| 角色 | 定义 |
| --- | --- |
| 游客 | 未登录用户。可以浏览广场和队伍详情，但不能创建队伍、申请加入队伍或查看联系方式。 |
| 登录用户 | 已完成注册并登录的用户。 |
| 申请人 | 已向某支队伍提交申请、当前正在等待审核的用户。 |
| 队伍成员 | 申请已通过，已加入某支队伍的用户。 |
| 队长 | 创建队伍的用户，同时作为该队伍的第一名成员。 |

### 3.2 用户资料

注册时填写以下信息：

- 手机号：必填，同时作为登录账号和唯一联系方式。
- 验证码：必填。
- 昵称：必填。
- 学校或公司：选填。
- 技能标签：选填。
- 希望担任的角色：选填。
- 个人简介或项目经历：选填。

其他规则：

- 每位用户自动使用一张系统默认头像，本阶段不提供头像上传或修改。
- 本阶段不提供用户资料编辑能力，资料在注册时一次确定。
- 手机号只用于登录和队内联系，不单独设置其他联系方式字段。
- 一个手机号只能对应一个账号。
- 昵称用于广场、队伍详情、申请审核和成员列表展示。

## 4. 登录、注册与退出

### 4.1 登录和注册入口

提供统一的登录/注册页面，页面包含“登录”和“注册”两个入口。

**注册流程**

1. 用户输入手机号。
2. 点击“发送验证码”。
3. 系统生成 6 位数字验证码，并在输入框下方直接展示该验证码。
4. 用户输入昵称、验证码，可按需填写学校/公司、技能、角色和简介。
5. 系统校验手机号和验证码。
6. 手机号未被注册时创建账号并自动登录。

**登录流程**

1. 用户输入手机号。
2. 点击“发送验证码”。
3. 系统生成 6 位数字验证码，并在输入框下方直接展示该验证码。
4. 用户输入验证码并登录。
5. 手机号未注册时提示用户先注册。

### 4.2 验证码规则

- 验证码为 6 位数字。
- 本阶段不真实发送短信，验证码生成后直接显示在页面上。
- 登录或注册时必须填写正确的验证码。
- 本阶段不实现验证码有效期、重发冷却和错误次数限制。
- 每次点击“发送验证码”会生成新的验证码。

### 4.3 会话与退出

- 登录成功后保持登录状态，刷新页面不退出登录。
- 页面顶部展示当前用户的昵称。
- 页面顶部提供“退出登录”入口。
- 退出登录后清理当前登录状态并返回登录/注册页面，以便切换其他账号。

## 5. 联系方式与可见性

### 5.1 联系方式范围

本阶段唯一联系方式为用户的登录手机号。

不提供：

- 微信号。
- 微信群二维码。
- 外部群链接。
- 站内聊天。
- 其他自定义联系方式。

### 5.2 手机号可见性

| 场景 | 手机号可见规则 |
| --- | --- |
| 游客 | 可以浏览广场和队伍详情，但看不到任何手机号。 |
| 普通登录用户 | 看不到其他用户的手机号。 |
| 申请人查看队伍 | 待审核或已拒绝时，看不到队长及队伍成员的手机号。 |
| 队长查看申请 | 可以看到申请人的手机号。 |
| 队伍成员查看队伍 | 可以查看同队成员及队长的手机号。 |
| 队长查看队伍 | 可以查看所有已通过成员及申请人的手机号。 |
| 广场队伍卡片 | 默认不展示手机号；仅当查看者已经是该队成员时，展示该队队长的手机号。 |

### 5.3 资料可见性

- 广场和队伍公开区域展示昵称和默认头像。
- 队长在审核申请时，可以查看申请人的昵称、默认头像、手机号、选填资料和申请内容。
- 已通过成员在队伍详情中，可以查看同队成员的昵称、默认头像、手机号、角色和选填资料。
- 非队伍成员不能查看队伍成员资料和手机号。

## 6. 广场

### 6.1 广场内容

广场展示所有队伍公告，支持查看组队中和已完成组队的队伍。

默认筛选“组队中”，用户可以切换到“已完成组队”或“全部”。

默认按队伍最后更新时间倒序排列；选择“全部”时，组队中的队伍排在已完成队伍之前。

### 6.2 队伍卡片信息

每张队伍卡片展示：

- 队伍名称。
- 项目一句话介绍。
- 队长昵称。
- 队伍状态：组队中 / 已完成组队。
- 当前人数 / 预设名额，并明确人数包含队长，例如“3/5 人（含队长）”。
- 招募角色及各角色剩余名额。
- 最后更新时间。
- 当前用户是该队成员时，展示队长手机号；其他用户不展示。
- 点击卡片进入队伍详情。

### 6.3 搜索与筛选

- 支持关键词搜索。
- 搜索范围包括队伍名称、项目简介和招募角色名称。
- 支持按状态筛选：
  - 组队中。
  - 已完成组队。
  - 全部。
- 无匹配结果时展示空状态，并提供“创建队伍”入口。

### 6.4 页面状态

- 加载中：展示加载状态。
- 加载失败：展示错误提示和重试入口。
- 无队伍：展示空状态和创建队伍入口。

## 7. 创建队伍

### 7.1 创建条件

- 用户必须已登录。
- 用户当前不能已加入或创建其他队伍。
- 用户创建队伍时，其名下所有待审核申请自动关闭，并标记为已拒绝，拒绝理由为“申请人已创建队伍”。

### 7.2 创建字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 队伍名称 | 必填 | 用于列表和详情展示。 |
| 项目一句话介绍 | 必填 | 用于队伍卡片展示。 |
| 项目完整介绍 | 必填 | 介绍项目背景、目标和当前进展。 |
| 项目方向/赛道 | 选填 | 例如 AI、Web、硬件等。 |
| 预设名额 | 必填 | 整数，至少为 1；包含队长，仅作为规划参考。 |
| 招募角色 | 必填 | 至少填写一个角色；每个角色包含名称、计划招募人数和角色要求。 |
| 硬性要求 | 选填 | 对申请人的必要条件。 |
| 加分项/偏好 | 选填 | 对申请人的非必要条件。 |

### 7.3 创建结果

- 创建成功后，当前用户成为队长。
- 队长自动成为队伍的第一名成员。
- 队伍初始状态为“组队中”。
- 队伍初始当前人数为 1。
- 每个招募角色的计划人数只统计通过该角色加入的成员，不包含队长。
- 队长在成员列表中标记为“队长”，不占用任何招募角色的计划人数。
- 创建成功后进入队伍详情页。
- 本阶段队伍创建后不支持编辑，创建前需要确认信息。

## 8. 队伍详情

### 8.1 基本信息

队伍详情展示：

- 队伍名称。
- 项目一句话介绍。
- 项目完整介绍。
- 项目方向/赛道。
- 队长昵称和默认头像。
- 队伍状态：组队中 / 已完成组队。
- 当前人数 / 预设名额，并标明包含队长。
- 每个招募角色的计划人数、当前已招人数和剩余名额。
- 成员列表，包括昵称、默认头像和所加入的角色；队长标记为“队长”。
- 硬性要求。
- 加分项/偏好。
- 最后更新时间。

不展示活动名称、活动时间、活动地点或组队截止时间。

### 8.2 人数与角色显示

- 总人数包含队长。
- 总预设名额仅作为规划参考，不会自动限制审核通过。
- 角色计划人数同样仅作为规划参考，不会自动阻止队长继续通过申请。
- 当实际人数达到或超过预设名额时，页面显示“已达到预设名额”提示，但队伍仍保持“组队中”。
- 当某个角色实际人数达到或超过计划人数时，该角色显示“已达到计划人数”，剩余名额显示为 0。
- 队长可以根据实际情况继续通过申请，直至主动完成组队。

### 8.3 不同用户看到的操作

| 查看者身份 | 可用操作 |
| --- | --- |
| 游客 | 可以查看公开队伍信息；创建队伍、申请加入或查看联系方式时需先登录。 |
| 登录用户，非队伍成员，未申请 | 队伍处于组队中时，可以申请加入。 |
| 申请人，待审核 | 查看申请状态，不能重复申请。 |
| 申请人，已拒绝 | 查看拒绝理由；队伍仍在组队中时，可以重新申请。 |
| 队伍成员 | 查看队伍详情、成员资料和队内联系方式。 |
| 队长 | 查看申请列表、审核申请、移除成员、完成组队、重新开放招募。 |
| 任何人查看已完成队伍 | 不能提交新申请；队长仍可重新开放招募。 |

## 9. 申请加入队伍

### 9.1 申请条件

- 用户必须已登录。
- 用户当前不能已加入或创建其他队伍。
- 队伍状态必须为“组队中”。
- 用户不能对同一队伍提交重复的待审核申请。
- 用户被拒绝后，可以在队伍仍处于组队中时重新申请。

### 9.2 申请表单

申请表单包含：

- 目标角色：必填，从该队伍当前招募角色中选择一个。
- 文字介绍：必填，最多 1000 字。
- 文字介绍用于说明技能、相关经历、可投入时间、加入动机等内容。
- 本阶段不展示附件上传入口。
- 申请提交后，待审核期间不能修改申请内容。

### 9.3 申请提交结果

- 提交成功后，申请状态为“待审核”。
- 页面明确提示申请已提交，正在等待队长审核。
- 用户可以前往“我的队伍”查看申请状态。
- 本阶段不提供主动撤回待审核申请的能力。

### 9.4 申请状态

| 状态 | 说明 |
| --- | --- |
| 待审核 | 已提交申请，等待队长处理。 |
| 已通过 | 队长已同意申请，用户成为队伍成员。 |
| 已拒绝 | 队长拒绝申请，或系统因队伍状态变化自动关闭申请。 |

### 9.5 自动关闭申请

以下情况，用户的待审核申请自动变为“已拒绝”：

- 用户加入了其他队伍。
- 用户创建了自己的队伍。
- 目标队伍被队长标记为“已完成组队”。

系统自动拒绝时展示对应原因：

- “您已加入其他队伍。”
- “您已创建队伍。”
- “该队伍已完成组队。”

被自动拒绝的用户，在目标队伍重新开放招募且自己未加入其他队伍时，可以重新申请。

## 10. 队长审核申请

### 10.1 审核信息

队长在队伍详情中可以看到申请列表，并查看每位申请人的：

- 昵称。
- 默认头像。
- 手机号。
- 学校/公司。
- 技能标签。
- 希望担任的角色。
- 个人简介或项目经历。
- 本次申请的目标角色。
- 文字介绍。
- 申请时间。
- 当前申请状态。

### 10.2 审核操作

队长可以：

- 同意申请。
- 拒绝申请。

**同意申请**

- 同意后，申请人立即成为队伍成员。
- 申请人获得申请时选择的目标角色。
- 队伍当前人数立即更新。
- 成员可以在队伍详情中看到其他成员和联系方式。
- 通过申请不会自动改变队伍状态，也不会自动停止招募。
- 若申请人此时已加入其他队伍，则不能通过该申请。

**拒绝申请**

- 拒绝理由为选填。
- 拒绝理由对申请人可见。
- 拒绝后，申请人可以重新申请该队伍。
- 同一申请只能被处理一次。

## 11. 队伍状态与生命周期

### 11.1 队伍状态

本阶段只有两个队伍状态：

| 状态 | 说明 |
| --- | --- |
| 组队中 | 队伍可以继续接收申请和审核成员。 |
| 已完成组队 | 队长手动结束组队，不再接收新的申请，也不再通过待审核申请。 |

### 11.2 完成组队

- 只有队长可以执行“完成组队”操作。
- 队长可以在任何时候手动完成组队，不要求人数达到预设名额。
- 完成组队时，所有待审核申请自动关闭，状态变为“已拒绝”，拒绝理由为“该队伍已完成组队”。
- 完成组队后，队伍状态显示为“已完成组队”。
- 已完成组队后，普通用户不能提交新申请。
- 已完成组队后，队长不能继续通过申请。
- 已完成组队的队伍仍可在广场中通过“已完成组队”筛选查看。
- 已完成组队的队伍仍保留成员列表和队内联系方式。

### 11.3 重新开放招募

- 只有队长可以执行“重新开放招募”。
- 重新开放后，队伍状态恢复为“组队中”。
- 重新开放后可以继续接收新申请和审核成员。
- 之前被自动拒绝的申请人可以重新申请。

### 11.4 移除成员

- 队长可以移除任意已通过成员，但不能移除自己。
- 被移除的成员不再是队伍成员。
- 被移除后，该成员失去查看队内成员联系方式的权限。
- 队伍人数立即更新。
- 移除成员不会自动改变队伍状态。
- 被移除的成员可以申请或创建其他队伍。

### 11.5 本阶段不提供的队伍操作

- 编辑队伍信息。
- 成员主动退出队伍。
- 队长转让。
- 队伍解散。
- 已解散状态。

## 12. 我的队伍

### 12.1 入口

- 首页和顶部导航提供“我的队伍”入口。
- 队长在入口处展示待审核申请数量提醒。

### 12.2 展示内容

“我的队伍”包含两个区域：

**我加入的队伍**

- 当前用户作为队长或成员加入的队伍。
- 展示队伍名称、队伍状态、当前人数 / 预设名额、自己的角色。
- 点击进入队伍详情。

**我的申请**

- 展示当前用户提交过、但尚未加入的队伍。
- 使用不同标记区分状态：
  - 待审核。
  - 已拒绝。
- 已拒绝记录展示拒绝理由。
- 队伍处于组队中且用户未加入其他队伍时，可以从该记录重新申请。
- 已加入的队伍不在“我的申请”中重复展示。

### 12.3 空状态

- 没有加入任何队伍，也没有申请记录时，展示空状态。
- 提供进入广场的入口。

### 12.4 状态更新

- 本阶段不实现实时通知。

## 15. 核心验收场景

1. 新用户使用手机号和 6 位验证码完成注册，填写昵称后自动登录。
2. 已注册用户使用手机号和验证码登录；退出后可以登录另一个账号。
3. 登录用户可以在广场搜索、筛选并查看队伍详情。
4. 登录用户可以创建队伍并自动成为队长和第一名成员。
5. 用户可以对组队中的队伍提交包含目标角色和文字介绍的申请。
6. 申请人可以在“我的队伍”中看到待审核状态。
7. 队长可以看到申请人资料和手机号，并同意或拒绝申请。
8. 拒绝理由选填，并对申请人可见；被拒绝后可以重新申请。
9. 申请通过后，申请人成为队伍成员，并能在队伍详情中看到同队成员手机号。
10. 队长手动完成组队后，队伍状态变为“已完成组队”，新申请和待审核申请被关闭。
11. 队长重新开放招募后，队伍恢复“组队中”，被自动拒绝的用户可以重新申请。
12. 队长可以移除已通过成员，被移除成员失去队内联系方式权限。
13. 队伍实际人数可以超过预设名额，预设名额和角色计划人数不会自动阻止审核。
14. 游客或其他非队伍成员无法看到队伍成员手机号。

## 16. 本阶段明确不做

- 活动上下文：活动名称、时间、地点、组队截止时间。
- 移动端适配。
- 附件上传。
- 头像上传与头像修改。
- 用户资料编辑。
- 申请人主动撤回待审核申请。
- 微信、群二维码、站内聊天。
- 队伍信息编辑。
- 成员主动退出。
- 队长转让。
- 队伍解散。
- 实时通知和消息推送。
- 验证码有效期、重发冷却和错误次数限制。
- 内容审核、举报和风控。
